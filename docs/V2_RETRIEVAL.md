# V2：可解释融合检索与邻窗上下文

V1 的 12 篇文档、切分方法、71 个原始片段编号及冻结题集没有改变。V2 在原有关键词和真实 BGE 向量检索之上增加可追踪的 RRF 融合，并把“用于排名的 Top5”和“送给生成器的扩展上下文”分开记录。

## 三种方式分别解决什么

- `keyword`：Jieba + BM25，适合命令、状态码、函数名、明确术语。
- `vector`：BGE-small-zh-v1.5 CPU + Chroma，使用语义相近的表达匹配资料。
- `hybrid`：两路各取 20 个候选，按原始排名融合，不直接相加不同量纲的分数。

融合公式为 `RRF(chunk) = Σ 1/(60 + rank)`；排名从 1 开始。BM25 为零或负分的候选不获得关键词票。每篇文档的同一章节最多保留两个片段；候选不足时如实返回更少片段。最终相同分数按片段编号排序，保证重现。

返回记录包含原始文档元数据、`ranks.keyword/vector`、独立的 `component_scores.keyword/vector` 和最终 RRF 分数。RRF、BM25、余弦相似度都不是“答案正确概率”。向量索引不存在或损坏会显式失败，不把关键词结果冒充融合结果。

## 为什么还要扩展上下文

长章节被切成多个窗口，命中窗口可能仅包含结论前半段。`expand_evidence` 保留 Top5 种子的原始编号、文字和来源，再在相同文档、相同章节里选择相邻窗口，总数最多 15。种子先保持检索顺序，新增窗口再按知识库原始顺序展示。

调用者提供的种子字典不能替换知识库原文。未知编号会被拒绝；也不会凭空合成“更完整”的新证据编号。扩展窗口只提供上下文，不制造模型答案，更不能触发审核或提交工具。

这属于上下文覆盖，不是新的 Top5 检索。因为只扩展已命中的同一章节，它不会提高章节级召回；可能改善同章节事实的完整性，是否改善回答仍需真实生成与语义复核。

## 本次真实检索回归结果

2026-10-25 使用已下载 BGE 模型和现有 Chroma 索引，30 题全部成功运行。全程没有调用 DeepSeek，模型 API 请求为 0。

| 方式 | 章节 micro Recall@5 | 按题 macro Recall@5 | MRR@5 | 全证据召回/有证据题 |
|---|---:|---:|---:|---:|
| BM25 | 28/29，96.55% | 96.15% | 94.23% | 25/26 |
| BGE | 23/29，79.31% | 82.69% | 69.23% | 21/26 |
| RRF 融合 | 26/29，89.66% | 92.31% | 84.94% | 23/26 |

融合改善了向量检索在 `test-02`、`test-17` 的漏召回，部分改善 `test-14`，但在 `test-01`、`test-14` 仍弱于 BM25。当前小型技术手册包含大量精确状态码和命令，BM25 在这组数据上更强。因此 BM25 继续作为默认选项，融合是可比较的候选，不宣称“增加技术组件就一定提高效果”。

具体失败：`test-01` 同时问“离线演示多少项、报告在哪里”，融合被“密钥没有 AI 结果”的相似章节挤占两个位置，漏掉报告章节；`test-14` 同时问临时服务结束及手工归属验证，融合提高了 VS Code 和路径类近似章节，挤掉第二个目标章节。它们展示的是复合问题排序不足，不能仅靠扩大同章节上下文解决。此次保留错误，不根据已观察回归标签调整权重。

29 是标注的章节总数；26 是存在标注证据的问题数。其余 4 题没有知识库证据，不进入召回分母。若检索失败，有标注的题按零召回计入分母，失败不会从分母消失。MRR@5 使用首次命中任一目标章节的倒数排名。

既有 holdout 已经在 V1 中观察过，本次仅是同一冻结材料上的回归，不是新的盲测。RRF 参数固定，没有使用标签调参；结果不代表实际企业问题分布。检索召回也不等于引用支持或最终回答准确率。

逐题原始排名、双路分数、扩展窗口、耗时和失败保存在本地 `reports/v2-retrieval-01/retrieval.json`，完整回归报告为同目录 `report.md`。公开 `docs/examples/v2-retrieval-01` 只保留指标、排序编号和分数，移除问题标签、文档摘录和原始路径。文档中的统计来自这次实际运行，未覆盖或改写 V1 的历史报告。

## 复现

在仓库根目录、已安装项目依赖并完成 `build-index` 的环境下：

```powershell
.\.venv\Scripts\python.exe -c "from pathlib import Path; from docflow_lab.config import Settings; from docflow_lab.retrieval_v2 import evaluate_retrieval; evaluate_retrieval(Settings(), Path('reports/v2-retrieval-02'))"
```

输出目录必须是新目录，避免覆盖历史结果。该命令只做检索，不调用付费模型，不自动下载向量模型。

掌握重点：解释一个关键词和向量排名不同的例子；手算一个片段的 RRF 分数；指出扩展窗口的来源；解释为什么融合没有超过 BM25。
