# DocFlow v1 项目计划与验收标准

原始目标：为北京约三个月的AI应用开发、AI后端技术实习准备一个能够解释、复现和修改的项目。长期就业地域偏向长三角。项目能力与岗位要求相关，具体岗位的实习周期仍需逐岗核对；项目完成不保证录用或薪资。

DocFlow与原EdgeSecLab独立：前者突出RAG、AI后端、人工审核和任务恢复，后者突出安全测试、日志审计和只读工具。保留EdgeSecLab，不把同一系统换名字重复展示。

## 首版范围

业务：技术问题→检索手册→带引用回复草稿→人工审核→明确提交本地模拟工单系统。单用户、CPU、单进程、Markdown/文本、一个工作流、一个本地提交工具。界面展示问题、引用、草稿、审核状态与记录。

| 模块 | 固定范围 |
|---|---|
| 知识库 | 12篇：6篇已有项目使用说明整理版＋6篇原创FAQ；保存来源、章节、版本 |
| 检索 | 关键词与向量比较，统一Top5；不伪装未构建的向量结果 |
| 生成 | answer、needs_info、out_of_scope；回答引用实际召回片段 |
| 审核 | 草稿版本和哈希绑定，旧审批不可用于新草稿 |
| 恢复 | 生成、审核、提交独立；SQLite检查点支持重启继续 |
| 提交 | 只写本地模拟系统；重复点击和先成功后超时重试只有一条回复 |
| 评测 | 10条开发＋20条冻结留出；引用存在性与语义支持分开 |
| 模型预算 | 默认离线替身；显式真实调用共计最多40次尝试 |

技术栈：Python3.11、FastAPI、SQLite、Chroma、BGE-small中文向量、LangGraph与DeepSeek。前端使用简单HTML/CSS/JavaScript，首版不增加大型前端框架、文档OCR、多工作流、企业集成或模型训练。

## 三周节奏

每天约90分钟项目时间，共21天约31.5小时。这是有协助的实现预算，学习者可按掌握情况放慢，不要求三周后独立重写所有模块。每个时段都应留下可复核输出或一段自己的解释。

| 天 | 动手任务 | 完成证据 |
|---|---|---|
| 1 | 按README启动默认demo与页面 | 说明离线模拟与真实模型区别 |
| 2 | 阅读两篇知识文档及元数据 | 指出来源、章节、版本 |
| 3 | 调用load_chunks看章节切分 | 自己打印一个章节的片段 |
| 4 | 用三个具体问题测试关键词检索 | 保存Top5与人工选中的证据 |
| 5 | 改写同一个问题并比较结果 | 解释词面变化造成的差异 |
| 6 | 阅读BM25和对应测试，改一个小变体 | 新断言和一次实际运行 |
| 7 | 复盘第一条链路，兼顾论文进度 | 口述问题如何到达相关章节 |
| 8 | 安装向量依赖、显式build-index | 保存真实构建结果或明确错误 |
| 9 | 同问题比较向量与关键词Top5 | 各记一个优点或失败例 |
| 10 | 阅读开发集与冻结协议 | 解释标签为何不能传给模型 |
| 11 | 运行开发题离线检索评测 | 查看召回分母与缺失证据 |
| 12 | 阅读草稿结构与引用校验 | 构造一个无效引用测试 |
| 13 | 核对一条草稿是否受到原文支持 | 写出事实、推断与遗漏 |
| 14 | 复盘前两条链路，兼顾论文 | 解释引用存在不等于正确 |
| 15 | 创建、批准、驳回和生成新版本 | 旧审批清除的实际记录 |
| 16 | 审核前停止服务后恢复 | 同一工单编号继续审核 |
| 17 | 模拟写成后超时并重试 | 同一回复编号、没有重复 |
| 18 | 阅读提交事务及唯一约束 | 自己解释幂等键组成 |
| 19 | 在预算内进行已授权的真实评测 | 保存实际用量与失败，不填预期数字 |
| 20 | 完整演示一条工单，整理README和错误例 | 可复现命令及真实报告 |
| 21 | 总复盘、模拟讲解、更新简历事实 | 三条链路讲清并指出限制 |

留出题只在材料冻结后用于正式检查，不把它当第二套提示调优练习。真实调用前先看共享预算，优先一次开发10题和一次留出20题，保留剩余额度处理有价值的演示，不要求用满。

## 工程验收

- 无审核或驳回的草稿不能提交，且数据库没有新增回复。
- 生成新草稿后旧审批失效；人工审批必须同时匹配版本与内容哈希。
- 服务重启后通过相同工单编号继续审核，不重新生成已有草稿。
- 模拟提交成功后超时，再次重试得到同一条回复；重复点击也不新增。
- 检索到的诱导文字不能调用提交、篡改审核记录或获得写权限。
- 输出引用只允许本次Top5；结构合法不当作语义正确。
- 未启用live时不调用真实模型；真实请求硬上限40，失败也计入。
- 模型结果、离线替身、实际测试、人工复核状态清楚区分。

实际通过情况、检索数字、模型调用、错误和限制在[RESULTS.md](RESULTS.md)填入，不能把上面的验收目标写成预先取得的效果。

## 个人掌握标准

1. 能把一个问题对应到实际文档、章节和chunk_id，解释关键词与向量结果差异。
2. 能说明每条关键回答引用哪段证据，并指出没有受到支持的推断。
3. 能解释审核版本、重启检查点、提交唯一约束，独立改一个小测试。

不用背下所有框架API，也不要求先刷完Python课程或LeetCode Hot100。需要查漏的基础从当前函数和测试中找；完成工程后继续用小练习证明自己可以读、改、调试。
