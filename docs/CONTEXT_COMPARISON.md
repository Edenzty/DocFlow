# 离线对照：完整文档章节与检索后回答

目标是练习回答一个明确问题：**对同一批问题，先检索再回答，与把全部资料放进上下文相比，有什么差异？** 这次交付是对照框架和复核流程，不是两种真实大模型方案的效果结论。

## 两组到底收到什么？

| 项目 | full_sections | bm25_top5 |
|---|---|---|
| 题目与语料 | 同一份冻结题集、同一知识库 | 相同 |
| 上下文 | 文档按原文件顺序，正文按章节完整提供 | 同一个 BM25 检索器返回最多5个片段 |
| 生成器 | 相同的确定性离线 `MockModel` | 相同 |
| 输出合同 | 相同字段、相同引用编号校验 | 相同 |
| 标签 | 预期结果、标注章节、标准事实仅留在评测侧 | 相同，不发送给生成器 |

**全文组按原文档顺序及标题提供全部章节正文**，不使用检索窗口的重叠切片；标题、来源和版本作为元数据提供。它不是把未处理的原始文件字节直接上传：元数据标记被解析，章节首尾空白被规范化。全文组引用编号对应完整章节，检索组引用编号对应片段，引用粒度不同，两组按文档和章节匹配标注。模拟生成器通常只摘录上下文开头两条，仅用于检验流程，不调用或模拟真实大模型的推理效果。两组的固定执行顺序、初建 BM25 耗时不计入逐题耗时，字符数不等于 token。现有 holdout 已被查看，当前运行只能叫回归，不能称为全新盲测。

## 如何运行

在项目根目录，先使用一个**不存在的新目录**：

```powershell
.\.venv\Scripts\python.exe -m docflow_lab compare-context --suite development --limit 3 --output reports/my-context-practice-01
```

如需覆盖全部30题，使用 `--suite all`，不传 `--limit`。启动前核验冻结清单，不能把改过的材料当作原题集；已有输出目录不能覆盖。

**此命令只允许离线模拟，既不读取密钥，也不调用真实模型或创建模型预算账本；没有 `--live` 参数。** 项目历史真实调用使用原 `.runtime/model-budget.sqlite3` 的共享40次预算，失败也计入。新副本不包含原账本，不能通过新建账本获得新额度。不要复制、删除、重置账本或替换模拟结果来绕开预算。

输出：

- `comparison.json`：每题两个方案的实际输入片段、结构化草稿、耗时、成功/失败和预期标签，方便追溯。标签不进入生成器。
- `report.md`：题数、完成数、决策匹配、引文结构检查与局限。模拟结果只展示评测管线。
- `review_template.json`：人工核对原文和答案。默认 `pending` / `uncertain`，不自动写出“支持”或“正确”。

## 对一个答案做人审

先在 `comparison.json` 找一题的 `question`、`context` 和 `draft`，对照 `review_template.json` 的 `required_facts` 与 `forbidden_facts`。重点看：引用是否真实存在；文档原文是否支持回答；关键事实是否缺失；资料不足时是否追问或拒答。

在 `review_template.json` 对应行填写：

- `status`: `done`；`reviewer`: 你的名字或自定义代号；`notes`: 写具体证据和原因。
- `citation_support`: `supported` / `unsupported` / `uncertain` / `not_applicable`。
- `fact_coverage`: `complete` / `incomplete` / `uncertain` / `not_applicable`。

保留没有检查的行为 `pending`。再汇总到一个不存在的文件：

```powershell
.\.venv\Scripts\python.exe -m docflow_lab review-context --comparison reports/my-context-practice-01/comparison.json --review reports/my-context-practice-01/review_template.json --output reports/my-context-practice-01/review-summary.json
```

汇总检查原始报告 SHA-256、题号和方案是否一致，防止将另一轮的评审混入。语义支持率的分母只有完成且能明确判断支持/不支持的样本；`uncertain` 和 `not_applicable` 单独计数。未复核分母为零，比例为 `null`，不伪装成0%或100%。人工复核报告只是当前审阅者对这些样本的判断，不是生产准确率。

## 指标和失败口径

- **完成率**：完成草稿 / 计划题数；生成失败和检索失败分别记录，失败不从总题数消失。
- **决策匹配**：`answer / needs_info / out_of_scope` 匹配 / 全部计划题数；未完成按不匹配。
- **库外拒答**：分别统计实际拒答 / 全部计划库外题，以及实际拒答 / 已完成库外题；未完成数量单列。可回答题被误拒使用已完成可回答题作为分母，未完成单列，避免把失败当作正确未拒答。
- **引用ID属于上下文**：完成的可回答草稿中，引用编号是否属于给定上下文。V1草稿合同只检查编号，不检查逐字引文；结构通过更不证明内容被引用支持。
- **语义支持与事实覆盖**：仅按人工已完成、可明确判断的复核分别计算，未复核继续显示待处理。
- **请求与耗时**：离线报告的供应商请求数为0，供应商 token 为 `null`；本机模拟耗时和上下文字符数不能当作真实模型延时和 token 费用。

## 一次20分钟动手练习

1. 运行三题，打开 `report.md`；确认模拟模式和真实模型请求0。
2. 在 `comparison.json` 找同一道问题的 `full_sections` 与 `bm25_top5`，比较输入章节/片段数量、来源及草稿。
3. 选择一组回答，自己读原文和标准事实；填写一条真实的人工复核并写一句理由，再运行 `review-context`。
4. 说出为什么“引用存在”“答案受到支持”“答全了”是三种不同检查；指出模拟对照不能回答哪种真实方案更好。

面试时可介绍为：**增加离线配对对照和人工语义复核流程，保留全量与检索两组输入、失败和分母，尚未运行真实模型对照。** 不要把模拟结果写成模型准确率或个人已完成的独立实测。
