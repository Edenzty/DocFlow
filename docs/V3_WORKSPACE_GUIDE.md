# DocFlow 3：可版本化知识库与技术支持 Agent

这一版把原来的固定资料演示扩展成可维护的本地应用：选择自己的 Markdown/TXT → 预览切分 → 发布 → 检索/生成草稿 → 人工审核。更新文档生成新修订与知识快照，已有工单继续保留生成时的证据；需要按新资料回答时，明确生成新草稿。

## 复用的开源框架与自己的代码

| 组件 | 实际用途 | 项目自己负责 |
|---|---|---|
| [LangChain Core](https://github.com/langchain-ai/langchain/tree/master/libs/core) | 用 `Document` 组织导入章节及来源元数据 | 文件校验、修订编号、发布事务 |
| [LangGraph](https://github.com/langchain-ai/langgraph) | 检索、生成、人工审核、提交节点及SQLite检查点 | 业务状态与知识快照绑定 |
| [Chroma](https://github.com/chroma-core/chroma) + BGE | 本地向量索引，语料/模型指纹隔离不同collection | 当前快照索引状态、显式构建 |
| [FastAPI](https://github.com/fastapi/fastapi) | API、参数校验和静态工作台 | 文档与工单接口、检索记录 |

这些是实际依赖与运行代码，不只是架构图中的名词。框架通过依赖使用，不把上游完整产品或代码声明成自己开发；本次没有复制其他产品的界面或业务源码。先前 Ragas 设计参考与许可证记录仍见 [开源评测说明](OPEN_SOURCE_IMPROVEMENTS.md)。

## 十分钟实际操作

1. 在项目根目录运行 `python -m docflow_lab serve`，浏览器打开 `http://127.0.0.1:8765`。
2. 进入知识库，在新导入面板填写文档ID `my-gateway`、标题与来源，选择UTF-8 `.md`/`.txt`文件，或粘贴：

   ```text
   # DFX900排查
   设备接口出现DFX900时，先检查队列长度，重试间隔配置为15秒。
   ```

3. 点击预览切分。核对章节、片段正文与修订编号。此时工作台查询仍使用已发布的知识库。
4. 点击发布。返回工作台，输入“设备接口出现DFX900时重试间隔配置为多少秒？”。关键词检索立即可用。默认生成是明确标注的离线摘录/模拟流程，真实DeepSeek沿用显式开关与原40次共享预算。
5. 把同一文档改为45秒，复用相同文档ID，重新预览、发布。新查询命中新修订；载入旧工单，它仍保存15秒的原始证据。
6. 在检索追踪里按工单ID筛选，查看查询、方法、快照、排名、来源、正文和耗时。这是检索执行记录，不是模型内部思维过程。
7. 在快照列表切换到旧快照，新查询恢复15秒。退役自定义文档后，新查询不再使用它；历史修订、旧工单和追踪仍保留。

## 向量索引怎样更新

关键词检索随发布切换。BGE/Chroma使用语料和模型指纹确定collection，文档更新后不会复用旧语料的向量结果，也不会悄悄改用关键词冒充向量。

页面“构建当前版本向量索引”仅使用本地BGE缓存。首次需要下载模型时，在终端明确运行：

```powershell
python -m docflow_lab build-index
```

需要重建原始12篇冻结语料的向量索引供历史评测使用时，运行 `python -m docflow_lab build-index --baseline`。新旧collection保留，回滚时可以复用该语料已有的索引。页面构建失败会明确报错，不构造模拟向量成绩。

## 可复现的离线演示

```powershell
python -m docflow_lab demo-knowledge --output reports/my-knowledge-v3-01
python -m pytest -q tests/test_workspace_lifecycle.py
```

输出目录必须不存在。演示执行真实SQLite事务、BM25检索和持久化，仅草稿生成使用模拟。它验证10项流程：预览不生效、发布命中、过期发布冲突、新修订替换、旧草稿保留、追问新版本、逐次追踪、回滚、退役和重启恢复，不评判真实大模型回答质量。

## 可以在面试里讲深的设计

- **修订与发布分开**：上传错误文档不会马上影响回答。并发发布带 `expected_snapshot_id`，过期页面得到409并重新确认。
- **快照而不是覆盖文件**：同一文档更新后，新旧片段编号不同。每个工单草稿版本绑定一个知识快照，Agent补充检索和邻窗扩展也使用同一快照。
- **人工编辑与重新生成区别**：手改旧草稿保留旧证据和快照；明确追问/重新生成使用当前知识库，并使旧审批失效。
- **索引不能只看存在**：Chroma collection同时绑定语料、模型和切分规则指纹；新语料索引未就绪就明确失败。
- **排错有实际记录**：检索错误也写入追踪，包括当时的快照与错误。引用存在仍不等于语义正确，需要人工核对。

冻结的12篇基础文档与评测题不在导入接口中改写；自定义资料只进入本地工作区SQLite，不随源码发布。单用户、单进程、本机运行范围保持明确；没有企业账号、多租户权限或生产部署成绩。代码工程完成与个人是否独立掌握分别记录。
