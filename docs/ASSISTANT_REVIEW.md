## 引用合法仍存在的五处问题

1. **dev-03：自相矛盾。** 对“差300秒会被拒绝吗”先答“会。”，随后正确写“差300秒不会被拒”。`guide-03-f0f92c2e54701b0c`明确边界允许。详细规则正确仍不能把开头歧义抹掉。
2. **test-01：检索遗漏与条件转移。** 没召回报告章节，回答没有给`report_path/report.html`，且承认资料未说明位置，没有编造路径。同时把显式启用Agent后缺密钥的`unavailable`状态，未经限定地接到默认离线demo上。`guide-01-55aa792301c7b45a`和`faq-04-1ab68fae2c78630d`需按各自条件理解。
3. **test-02：信息不全与重试前提表达过宽。** 没召回配置输入章节，A保留20得到替代FAQ支持，但B未受影响没有完整回答。提及401后又笼统说“被拒后重发旧nonce会409”，容易误读为签名失败也消费nonce；这里只认定条件不清，不虚构模型明确说了所有401都消费nonce。
4. **test-13：添加了未获支持的强制位置。** 保留`succeeded`和来源缺口的主结论正确；“来源缺口应记录在observations中”超出了`guide-04-e2df879a3ae24e1b`，该段只说observations记录数据质量提醒，未规定所有覆盖缺口必须归入此字段。
5. **test-20：库外拒答正确，额外专业判断没有检索依据。** 未开处方，决策适合。但实际引用都是技术/注入段落，不能支持新增的“胸痛可能涉及紧急健康风险”医学判断。这里评价证据范围，不认定提醒就医本身不当，也不把技术引用伪装成医疗来源。

## 检索缺口和回答错误分开看

- test-14：未召回“报告文件与临时服务”和“手工验证归属”，模型转为`needs_info`，漏掉demo结束后服务关闭、`serve`与`config`的明确答案。主要表现是检索缺口导致保守但不完整的回答，没有捏造服务命令。

- test-15：追问方向合理，但漏问具体执行命令，并附加较多审计输入限制。test-19：库外拒答合理，附带引用却是费用和密钥技术段落，不能作为招聘事实依据。
- dev-10：没有编造真实生产密码或命令，但未明确提示补充相应可信设备手册，完整性仍有一项遗漏。
