# 第一次90分钟：亲自走通一条技术工单

本文是V1单次RAG练习；新版工作台请选择“单次RAG”复现。V2工具循环、追问和后台任务练习见[V2指南](V2_GUIDE.md)。

今天的目标不是重写整个Agent，而是解释并验证三条链路：**问题怎样找到章节、草稿怎样引用证据、审核后怎样可靠提交。** 默认全程离线，不需要模型密钥，不消耗请求预算。没有完成的步骤下次继续，不因工程代码已交付就默认你学会。

## 0—15分钟：启动并看清离线标记

在VS Code打开整个`D:\personal development\docflow-lab`目录，选择`.venv`解释器，新开PowerShell终端。如果还没有虚拟环境，先按README安装；已有环境无需每天重复安装。

```powershell
Set-Location -LiteralPath 'D:\personal development\docflow-lab'
.\.venv\Scripts\python.exe -m docflow_lab demo --output reports/my-demo-01
.\.venv\Scripts\python.exe -m docflow_lab serve
```

第二条命令保持运行，浏览器打开`http://127.0.0.1:8765`。端口被占用时先确认是不是自己上次的服务；也可用`serve --port 8766`，对应打开新端口。停止服务用该终端的Ctrl+C。不要关闭其他不认识的进程。

在页面确认当前为离线模拟、知识文档数12、真实模型开关未勾选。默认`serve`没有开`--live`，即使电脑已配密钥也不能直接付费生成。

**验收：**用自己的话说出“文档检索”“离线模拟摘录”和“真实模型生成”三者的区别。离线模式有一段像回答的文字，不代表已测试真实模型理解能力。

## 15—30分钟：亲自读一个片段

先打开`knowledge/guide-02-auth.md`，读“身份认证与设备授权”。再打开`docflow_lab/retrieval.py`，只看`Chunk`、`load_chunks`与`_sections`附近，不要求通读整文件。

在项目根目录新建自己的`learning_chunk.py`，用下面几行观察数据：

```python
from pathlib import Path
from docflow_lab.retrieval import load_chunks

chunks = load_chunks(Path("knowledge"))
for chunk in chunks:
    if chunk.document_id == "guide-02" and chunk.section == "身份认证与设备授权":
        print(chunk.chunk_id, chunk.document_id, chunk.section)
        print(chunk.text)
```

运行`.\.venv\Scripts\python.exe learning_chunk.py`。这里`chunks`是片段列表，`chunk`是其中一条，`if`筛选章节；输出可能有多个片段，因为长章节会切分。`chunk_id`标识片段，`document_id`标识整篇文档，`section`保留章节标题。

**自己改两处：**改成读取`guide-03`的“哪些响应消耗nonce”；然后只打印每段长度，核对是否不超过220字符。只查当前需要的`for/if/len`语法，不先刷完整基础课程。

**验收：**解释为什么不能只存一大段正文，以及为什么回复需要引用片段而不是仅写“参考说明书”。

## 30—45分钟：从问题找到证据，再生成草稿

页面输入：“我用key-a读取device-b的配置，返回403且reason为device_forbidden，应该怎么排查？”选择关键词检索，先点“仅检索”。

逐条看最多5个结果，找出真正支持答案的章节，记录一个chunk_id。看见“签名”“设备”等共同词不等于已找到根因；需要原文明确说明身份验证和设备归属的区别。

再点“检索并生成草稿”，核对离线标记和引用。当前Mock会摘录召回内容，不会像真实模型一样可靠地综合所有建议。请自己把最重要的两条事实写在纸上：A默认允许操作谁、403与401在此例中如何区别。

打开`docflow_lab/model.py`，只读`Draft`和`validate_draft`。理解三项检查：`answer`至少一个引用、不得重复引用、引用必须属于本次Top5。思考：原文只是说“签名通过”，模型却写“真实操作者一定是A本人”，为什么编号存在也不能让这句话成立？

**验收：**能指着一条草稿建议，指出对应原文；也能说出存在性校验没有检查哪类语义错误。

## 45—60分钟：审核当前版本，并做一次重启恢复

先保存页面上的工单编号。保持草稿待审核，在服务终端Ctrl+C停止，再用相同命令启动`serve`。回到页面，在“恢复已有工单”输入编号，点击载入。

预期仍能看到同一版本草稿、证据和待审核状态。检查内容后批准当前版本，确认批准后并没有自动写入回复。先不要提交。

读`docflow_lab/workflow.py`的`_review`和`_await_submit`，再读`storage.py`的`approve`：前者在两个不同节点等待输入，后者把版本和草稿哈希写入审批记录。重启后能继续，依靠的是SQLite文件和LangGraph检查点，不是浏览器页面记忆。[中断说明](https://docs.langchain.com/oss/python/langgraph/interrupts)。

**再做一个新版本实验：**点击生成新版本，应看到版本增加、原批准失效，需要重新审核。不要认为“这张工单曾批准过”就能批准所有后续内容。重新批准你实际核对过的新版本。

**验收：**解释为什么批准与提交分两步，以及为什么旧审批不能复用。

## 60—75分钟：制造一次先写成后超时

勾选“模拟：提交成功后响应超时”，点击“提交到本地工单”。这一次故意在本地事务写成后返回超时，所以可能同时看到失败提示和已存在回复。

记下回复编号，再点“重试失败步骤”。预期状态变为提交完成，并且回复编号保持一致。刷新页面、再载入工单，回复仍只有一条。调用记录应能看到写入和重复确认的区别。

读`storage.py`的`submit`，只找三个位置：核对审批的版本和哈希、查询已有reply、插入后提交事务。`idempotency_key`由工单编号、版本和草稿哈希组成；`replies`的工单唯一约束防止再插一条。不能只靠按钮变灰保证不重复。

**验收：**解释“客户端超时”为什么不等于“服务端没执行”，以及这里为什么可以重试同一版本。这个保证只覆盖本地模拟表，不能直接承诺真实第三方系统也具有相同事务边界。

## 75—90分钟：完成一个独立的小练习

只选一个，自己写并说明每个断言；不要让工具一次生成全部答案。

| 练习 | 自己完成的工作 | 验收 |
|---|---|---|
| 检索练习 | 在`learning_chunk.py`中换一个章节，统计该章节片段数和最长长度 | 能解释列表、循环、属性和`len` |
| 引用练习 | 找到现有引用校验测试，添加“引用不属于本次结果”的变体 | 先预测失败原因，再运行单项pytest |
| 状态练习 | 参照现有工作流测试，增加“驳回后直接提交被拒”的变体 | 除返回错误，还检查没有新增回复 |

先执行`.\.venv\Scripts\python.exe -m pytest --collect-only -q`看现有测试名称，选最相关的一个读，不从全仓库第一行开始背。已有测试能通过不代表新增练习做对；要检查新增断言确实失败过，再恢复正确预期。

如果只完成启动和检索也可以，下一次从草稿引用继续。今天不要求下载向量模型、不要求接真实API、不要求读完LangGraph源码。基础薄弱时，把查漏绑定到眼前这一行代码，再回到项目。
